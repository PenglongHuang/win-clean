# 扫描结果为空与父子目录混排修正

依据真实用户反馈：B 盘规则扫描 findings=0；深入扫描在 180 秒预算后仅报告约 60.8 GB，并把父目录及其各层子目录同时列为大户。

根因：规则库主要绑定系统用户目录，没有把非系统盘发现接入清理候选；目录展示直接对所有祖先按大小排名；逐文件沿祖先路径累加影响性能；固定时间截断使遍历覆盖不足。

修正：

- 广度遍历，目录自身字节汇总后从叶向根聚合一次；规范化并剔除重叠扫描根。默认取消时间截断，保留取消与可选 BudgetSeconds。
- 完整扫描的缓存目录及未完成下载文件成为会话级 L4 候选，手动勾选且仅隔离，不写长期规则。名称命中属于弱证据，页面明确要求核对影响，不将体积或未使用时间视为删除依据。
- 嵌套缓存折叠、候选与已有规则重叠排除；系统报告区域、Windows 区域、包含项目仓库/依赖的缓存目录不得升级成可执行候选。合并时重新检查候选目录，兼容旧快照。
- 目录返回 parent、directBytes、complete，页面只显示同层子目录，可点击下钻；扫描根不与子目录混排。此处去除展示重叠，不宣称逻辑大小已经去除 NTFS 硬链接的物理重用。
- 没有“建议清理”但有 L4 时自动显示“需要确认”，各分类显示项目数量；空间分布默认展开，避免用户只看到 0 B。
- OpenRun 仅打开数据目录内扫描已完成的会话，方便更新后复用结果，不触发执行。

回归覆盖：重叠根、嵌套缓存、私人文件、Git/依赖数据、仅报告边界、重复合并、树状同层筛选、选择收益去重、取消与预算。浏览器验证需要确认候选自动可见、下钻与窄屏布局。
